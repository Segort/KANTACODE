# Прозрачная вакансия

MVP формирует JSON-отчёт для редактора вакансий Калининградской области. Он отмечает пропуски, неоднозначности и противоречия в условиях работы и формулирует вопросы к работодателю.

## 1. Подготовка

Установите Python 3.11+ и [uv](https://docs.astral.sh/uv/getting-started/installation/). Из корня проекта выполните в PowerShell.

```powershell
uv sync
Copy-Item .env.example .env
```

В Linux используйте `cp .env.example .env`. Зависимости описаны в `pyproject.toml`: httpx, Pydantic, OpenAI SDK и python-dotenv.

| Настройка | Назначение |
|---|---|
| `API_URL` | Источник вакансий. По умолчанию регион 39 портала «Работа в России» |
| `MAX_VACANCIES` | Предел загруженных карточек в fetch, по умолчанию 40. Размер страницы до 20 |
| `REPORT_PATH` | Путь к отчёту. Параметр `--output` имеет приоритет |
| `LLM_BASE_URL` | URL OpenAI-совместимого API с поддержкой Structured Outputs |
| `LLM_API_KEY` | Ключ выбранного провайдера. Локальный Ollama игнорирует значение `ollama` |
| `LLM_MODEL` | Имя модели, по умолчанию `qwen2.5:7b` |

## 2. Проверка на локальных данных без платного аккаунта!

1. Установите [Ollama](https://ollama.com/download), запустите приложение или выполните `ollama serve`, если сервер ещё не работает.
2. Выполните `ollama pull qwen2.5:7b`.
3. Оставьте настройки LLM из `.env.example` и запустите из корня проекта.

```powershell
uv run python main.py --mode verify --input examples/sample_input.json --output reports/verify.json
```

Для проверки подставьте свой JSON. Режим verify читает все записи из `results.vacancies[].vacancy`. URL портала и лимит в этом режиме не используются. После скачивания модели и зависимостей можно отключить интернет и запустить команду через `uv run --offline`. Анализ идёт через локальный адрес 127.0.0.1.

В `examples/sample_input.json` лежит предоставленный учебный файл из 10 вакансий. В `examples/sample_report.json` сохранён результат локального прогона Qwen. Сопоставляйте входные карточки и отчёт по `id` и `vacancy_id`.

Учебные карточки передают описание условий в `duty`, `requirements` и `requirement.qualification`, а отдельного `description` у них нет. Анализатор сравнивает эти поля между собой. Нулевые границы зарплаты учитываются как незаполненные значения, одна положительная нижняя граница означает оплату «от» указанной суммы. Если `vac_url` отсутствует, в отчёте записывается `null`.

## 3. Рабочий режим и расписание

```powershell
uv run python main.py --mode fetch
```

`main.py` — точка входа. После загрузки карточек сервис удаляет дубли по ID, сохраняя последнюю входную запись для каждого ID. Затем он выделяет структурированные поля и описание и отправляет их модели. Из ответа сохраняются замечания, прошедшие проверку формата и цитат. Цитаты сверяются с указанным полем карточки. Дополнительные правила убирают замечания о пропуске, когда карточка уже содержит название должности или адрес, и проверяют отсутствие данных об оплате. После успешного анализа всех карточек отчёт заменяется атомарно. При ошибке команда возвращает код 1 и сохраняет предыдущий отчёт.

Для запуска по расписанию на Linux перенесите строку из `crontab.example` в `crontab -e`, указав реальные абсолютные пути. По умолчанию запуск ежедневно в 08:00 по времени сервера. До включения расписания запустите команду вручную и убедитесь, что выбранный сервис модели доступен тому же пользователю.

## 4. Поля отчёта

Корневое значение — массив объектов вакансий.

| Поле | Содержание |
|---|---|
| `vacancy_id` | ID вакансии из источника |
| `url` | Ссылка на карточку или `null` |
| `issues` | Массив замечаний. При отсутствии замечаний `[]` |
| `issues[].topic` | Одно из семи проверяемых условий |
| `issues[].kind` | `missing`, `ambiguous` или `contradiction` |
| `issues[].evidence` | Массив ссылок на источник с полями `source_field` и `quote`. Для пропуска одна запись с пустой цитатой, для неоднозначности одна цитата, для противоречия две |
| `issues[].problem` | Что мешает понять условия |
| `issues[].recommendation` | Что редактору уточнить у работодателя |

## 5. Как проверить

```powershell
uv run python main.py --mode verify --input examples/sample_input.json --output reports/verify.json
```

Ожидаемый результат — отчёт по 10 учебным вакансиям. Повторный запуск сохраняет одну запись на ID, а сбой API оставляет предыдущий отчёт доступным.
